# job-market-tracker

A daily snapshot of new software-engineering job postings (full-stack, frontend,
backend, TypeScript/React/Node and similar), pulled from free public job feeds
and stored in this repo as plain JSON.

> **About the commits in this repo.** The `data: job snapshot …` commits are made
> automatically, once a day, by a scheduled GitHub Actions workflow
> ([`.github/workflows/daily.yml`](.github/workflows/daily.yml)). They are
> authored as the repo owner and pushed with the workflow's default
> `GITHUB_TOKEN` (no personal access token). The point is to build up a running
> dataset of the job market over time. A commit only happens when that day's
> fetch succeeded and produced a real snapshot; if any source fails, the run
> fails visibly and nothing is committed. Code changes go through pull requests
> like any other project.

## What gets recorded

One file per day at `data/YYYY/MM/YYYY-MM-DD.json`:

```jsonc
{
  "date": "2026-10-06",
  "generatedAt": "2026-10-06T14:36:14.481Z",
  "sources": [
    { "source": "greenhouse", "fetched": 2703, "matched": 62, "new": 62 }
    // ...one entry per source
  ],
  "postings": [
    {
      "id": "greenhouse:vercel:6199608004",
      "source": "greenhouse",
      "company": "Vercel",
      "title": "Software Engineer, Agentic Infrastructure",
      "location": "Hybrid - San Francisco, New York City",
      "remote": false,
      "url": "https://job-boards.greenhouse.io/vercel/jobs/6199608004",
      "postedAt": "2026-09-17T21:56:20.000Z",
      "tags": []
    }
  ]
}
```

A file only lists postings that are **new**: they match the criteria,
pass the age filter described under [Configuration](#configuration), and were
not already recorded on an earlier day or from another source the same day.
Two postings count as the same if they share a source id, a normalized URL
(tracking parameters stripped), or
the same company + title + location. The first snapshot is a baseline, so it
contains every matching posting that passes the age filter.

[`examples/snapshot-example.json`](examples/snapshot-example.json) is a
sample from a real local run, trimmed to eight postings (the per-source counts
are from the full run). `matched` counts postings that passed the keyword,
location and age filters; `new` is what remained after dedupe.

## Sources

All sources are free, need no API key, and are fetched once a day with a
descriptive `User-Agent`, sequentially, with pauses between requests and
retries with backoff on 429/5xx. `Retry-After` delta-seconds and HTTP dates are
honored; a requested wait over 60 seconds fails the request instead of retrying early.

| Source | Endpoint | Notes |
| --- | --- | --- |
| Greenhouse job boards | `boards-api.greenhouse.io/v1/boards/{board}/jobs` | Public board API for each company in the config. |
| Lever job boards | `api.lever.co/v0/postings/{board}?mode=json` | Public postings API for each company in the config. |
| [Remotive](https://remotive.com) | `remotive.com/api/remote-jobs` | Remote jobs. Remotive asks API users to link back and credit them, and to call at most a few times a day; every Remotive posting here keeps its remotive.com URL. Their feed is delayed by 24 hours. |
| [Arbeitnow](https://www.arbeitnow.com) | `arbeitnow.com/api/job-board-api` | Free public API (first few pages only). Mostly European jobs, so few pass the US/remote location filter. |
| [Hacker News "Who is hiring?"](https://news.ycombinator.com/submitted?id=whoishiring) | `hn.algolia.com/api/v1` | Top-level comments in the newest available hiring thread. Company, title and location are parsed from the first line of each comment by heuristics, so expect some noise. |

Ashby, Workday and anything behind a login are not used.

## How it works

1. `npm run snapshot` loads [`config/criteria.json`](config/criteria.json) and
   all earlier snapshots from `data/`.
2. Each enabled source is fetched (ATS boards first, so the employer's own
   posting wins over an aggregator copy). If **any** source errors, or returns
   no postings at all, the command exits non-zero and writes nothing. A partial
   day would skew the trend, so the day is left as a gap instead. No enabled
   sources also fails without writing. Individual empty Greenhouse/Lever boards
   warn on stderr but are legitimate; the combined feed for each enabled source
   must still contain postings.
3. Postings are normalized, filtered by keyword / exclusion / location / age,
   and deduplicated against each other and every earlier day.
4. Today's file, `SUMMARY.md` and the README section are written. A successful
   day with zero new postings is still recorded (as `0 new postings`).
5. The daily workflow runs only on `main`, commits those files as
   `data: job snapshot YYYY-MM-DD (N new postings)` and pushes to `main`.
   Pushes made with `GITHUB_TOKEN` do not trigger CI or other workflows.

Re-running on the same day rebuilds that day's file rather than adding to it.
GitHub disables scheduled workflows after 60 days without repository activity;
if the trend table shows a long gap, that is the likely reason.

## Running locally

Requires Node 22.18+ (TypeScript runs directly through Node's type stripping, no
build step).

```sh
npm ci
npm test                                  # fixture-based tests, no network
npm run -s snapshot -- --dry-run > out.json  # live fetch, print JSON, write nothing
npm run snapshot -- --root /tmp/jmt       # live fetch, write data/ + SUMMARY.md under /tmp/jmt
npm run snapshot -- --help
```

Running `npm run snapshot` with no options writes into this checkout's `data/`.
`--date` must be a real UTC calendar date and is validated before any fetch or write.

## Configuration

[`config/criteria.json`](config/criteria.json) holds the search criteria, all
generic:

- `keywords`: a posting must mention one in its title or tags.
- `excludeKeywords`: titles containing any of these are dropped (interns,
  managers, sales, ...).
- `locations`: accepted locations for on-site/hybrid roles (US cities and
  "United States" variants).
- `remoteRegions`: remote roles pass if they are unrestricted or their location
  mentions one of these regions or one of the configured `locations`.
- `maxAgeDays`: ignore postings whose source date is more than this many days
  before the snapshot date (UTC midnight). Undated postings pass. Greenhouse
  uses `first_published` when available, falling back to `updated_at`, so a
  recently updated older posting can pass.
- `skills`: terms counted for the "top skills" tables.
- `sources`: enable/disable each source and list Greenhouse/Lever board slugs.

Matching is case-insensitive on whole terms, so `node` matches "Node.js" but
`intern` does not match "Internal".

## Limitations

- Skill counts only look at titles and source tags; descriptions are not
  fetched.
- The company list is a small hand-picked set, not the whole market.
- HN parsing is heuristic.
- Aliases of postings dropped as duplicates are not persisted. Rarely, an
  aggregator copy dropped on one day can reappear as new on a later day if
  its title changes.
